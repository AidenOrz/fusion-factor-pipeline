# 阶段 E：冻结评分器等价校验（2026-10-18）

> 判据来源：`docs/HANDOFF.md` 阶段 E 第 6 项——"用冻结配置重新物化评分器，与
> `runs/factor_evaluation_v1_b2_frozen_2026-08-28/*/predictions.parquet` 逐键逐分一致（不重新训练、不看标签）。
> 不等价则停线诊断，不得带病进入前向。"
> **结论：两个模型均逐值完全一致（max abs diff = 0），门通过。**

## 1. 为什么这一关必须先过

前向观察拿到的分数，是"同一份代码 + 同一份冻结配置"在今天重新训练出来的。如果这套流程
今天跑出的历史预测与当时存档的不一致，那么前向分数就**不能与历史记录相提并论**——
不是"差一点"，而是"两个不同的量"。所以这一关的判据是**精确相等**，不是近似。

## 2. 做法

对冻结配置里的每个模型：

1. 取**同一份**面板 `data/panel_fusion_b2_adjudicated_2026-08-27.parquet`；
2. 只在**选择期** 2023-06-30~2024-09-12 上训练（560,456 行），种子 42/43/44 等权集成；
3. 对**评价期** 2024-10-22~2025-12-31 预测；
4. 与存档 `predictions.parquet` 按 `(date, code)` 外连接，逐行比对 `prediction`。

不重新调参、不重新选种子、不用评价期标签参与拟合。

## 3. 结果

| 模型 | 比对行数 | 键集合一致 | max abs diff | 超差行数 | IC（存档 / 重建） | 等价 |
|---|---|---|---|---|---|---|
| `huber_b2_raw_rank` | 518,372 | 是（0 多 0 缺） | **0.0** | 0 | 0.134586 / 0.134586 | **是** |
| `huber_b2_neutral_rank` | 518,372 | 是（0 多 0 缺） | **0.0** | 0 | 0.125299 / 0.125299 | **是** |

- 两个模型都是**双侧零差异**：不是"够接近"，是每一位都相同。
- IC 也逐位复现（0.134586 / 0.125299），说明不只是点值一致，聚合路径也一致。
- 存档文件 sha256 已记入报告，便于日后核对存档本身有没有被改过。

产物：`runs/scorer_equivalence_2026-10-18/equivalence_report.json`

## 4. 这一关证明了什么、没证明什么

**证明**：冻结配置 + 当前代码路径可以**确定性地**重现历史评分。训练是确定性的
（`n_jobs=1`、固定种子、固定权重构造），代码没有在这段时间里悄悄漂移。

**没有证明**：

- 不证明 alpha 有效。等价校验只回答"是不是同一个东西"，不回答"是不是好东西"。
- 不证明前向期的分数落在同一分布。这由前向观察的评分分布诊断回答（见预注册报告 §6）。
- 不覆盖 `alpha056`。该特征在冻结 37 特征清单之外（已核对：
  `config/factor_pool_b2_post_lofo_retry_starter_2026-08-28_features.json` 共 37 项，不含 `alpha056`），
  故 `bridge/forward_scoring.py` 里的 `FEATURE_COLUMNS_EXCLUDED = {"alpha056"}` 对本次比对无影响。

## 5. 复现

```powershell
python bridge/scorer_equivalence.py --out-dir runs/scorer_equivalence_2026-10-18
# 退出码 0 = 全模型等价；1 = 存在不等价（此时按判据必须停线诊断）
```

单模型复核可加 `--models huber_b2_neutral_rank`（约 5 分钟/模型）。

## 6. 边界

- 本校验**不改动**任何冻结产物，只读取并比对。
- 若日后因 LightGBM 版本升级导致浮点差异，应视为**真实的不等价**并按判据停线诊断，
  不得通过放宽容差来"通过"——容差写死在 `EXACT_TOLERANCE = 0.0`。
