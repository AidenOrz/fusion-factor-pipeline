# 用"逐值复现"决定能否信任一个外部数据源

## 适用场景

需要从第三方接口补一段**已有本地归档**的行情/指数/基本面时间序列时，
尤其是这段数据会进入标签定义、验收门槛或任何不可回退的结论。

## 现象

- 本地归档在某日中断，第三方源能拿到更远的日期。
- 接口返回的数值"看起来"对：量级合理、涨跌幅像指数、日期对得上。
- baostock 这类库对不支持的代码**返回 0 行且 `error_code="0"`（成功）**，
  并不报错——不特意检查就会当成"该日无数据"。

## 根因 / 洞见

**"看起来对"与"是同一个东西"是两件事。** 外部源的三个真实风险，都不是靠肉眼能发现的：

1. **字段顺序不同**。腾讯 `fqkline` 的返回是 `date, open, close, high, low, volume`，
   close 在 high/low **之前**；本地 CSV 是 `date, open, high, low, close`。
   照抄本地顺序解析，会把**收盘价与最高价对调**，而表仍然"像个正常行情表"。
2. **复权基期不同且非恒定比例**。本项目实测 baostock 与本地归档的收盘价差值随日期变化
   （`600519` 单因子拟合残差 28.02 元），直接拼接会在接缝引入假跳空。
3. **同名不同物**。`000985.csv` 在本地 K 线目录里是**股票**大庆华科，
   而 `_bench_000985.csv` 才是**指数**中证全指。同代码不同文件，含义完全不同。

## 推荐做法

**在写盘之前做逐值比对，不一致就抛错，不给"容差"留口子。**

```python
merged = local.merge(fetched, on="date", how="inner", suffixes=("_local", "_fetched"))
for column in ("open", "close", "high", "low"):
    diff = (merged[f"{column}_local"] - merged[f"{column}_fetched"]).abs()
    if not float(diff.max()) == 0.0:
        raise BenchmarkSourceError(f"mismatch on {column}")
```

配套要求：

- **重叠长度下限**（本项目用 200 日）：重叠太短时"零差异"可能是巧合。
- **本地日期不得缺失**：只补新日期，不允许外部源"重排"已有历史。
- **只写新增段**，原归档永不改写；新增段单独成文件 + `.meta.json` 记录源 URL、
  重叠验证明细、输出 sha256。
- **测试里放一条"故意对调 high/close"的用例**，确保验证逻辑真的能失败——
  一个永远通过的校验等于没有校验。

## 验证依据

2026-10-18 实测：腾讯 `sh000985` 与本地 `_bench_000985.csv` 在 **1,098 个重叠交易日**上
open/high/low/close **max abs diff 全部 = 0**，本地日期 0 缺失，补齐 59 个交易日
（2026-07-20 ~ 2026-10-16）。该结果使前向窗口 39 个交易日的标签得以生成。

## 适用边界

- 逐值相等只在**同一复权基期**下可期待。若两源复权方式不同（如后复权 vs 前复权），
  应改用分段常数因子对齐（见 `baostock_local_kline_splice.md`），不要指望逐值相等。
- 逐值相等**不保证未来一致**。接口改版、指数成分调整算法变更都可能让新数据偏离，
  故每次延伸都重新验证，不复用上一次的结论。
- 该做法要求本地归档存在且可信。若本地归档本身来源不明，逐值比对只是"两个源互相印证"，
  不构成独立证据。
