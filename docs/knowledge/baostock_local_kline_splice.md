# baostock 与本地 K 线归档的拼接边界（价格基准不同，量与额可对齐）

## 适用场景
本地 K 线归档（`A_SHARE_KLINE_DATA_ROOT` 的逐股 CSV）止于某日（2026-07-24），
需要把面板/因子延伸到更新日期（例如 baostock 可查到 2026-10-16）时，
判断"能否直接拼接两个来源"。

## 现象
以 2026-06-01..2026-07-24 重叠段逐日比对（6 只股票）：

| 列 | 结果 |
|---|---|
| `volume` | 本地值 × 100 == baostock 值（偏差 ~1e-6，纯浮点）→ **口径为"手 vs 股"，可精确换算** |
| `amount` | 两端一致（偏差 ~1e-6） |
| `close` | **不一致，且差值随日期变化** |

## 根因/洞见
本地归档与 baostock 的**前复权基准不同**，差异**不是常数缩放**：
- 对 `000001`，本地隐含因子在重叠段有 8 个不同取值（0.9667~1.0），
  baostock 只有 0.9473/0.9784 两个；
- 单因子拟合残差远超 2 位小数舍入容差（如 `600519` 残差 28.02 元）。

即：**不能**用"乘一个常数"把 baostock 价格对齐到本地序列。
接缝处直接拼接会在 `close` 上引入一根假跳空（实测 `600000` 为 −4.47%），
进而污染 `pct_change`、`ret_*`、`atr_relative`、`position_ema20` 等全部价格类派生列。

## 推荐做法
1. **优先只用一个来源**。若能取得本地归档的延续 CSV，就不要混源。
2. 若必须用 baostock 延伸：
   - 成交量与成交额可直接换算（本地"手" × 100 = 股），这块是安全的；
   - **价格必须做基准对齐**：在重叠段估计逐日因子
     `f(t) = local_close / baostock_adj_close`，并把该因子按"最后一个重叠日的因子"
     或"因子序列外推"应用到新数据；**不得**假设因子恒定。
   - 对齐后**必须**验证：接缝日 `close` 相对前一日的收益不出现异常跳变
     （对照该股历史收益分布，如 |ret| 不得超过历史 p99.9）。
3. 无论哪种来源，延伸后都要跑 `(date, code)` 唯一性断言与"历史行逐列不变"回归。

## 验证依据（2026-10-17 实测）
- 6 只股票 × 39 个重叠交易日：成交量/成交额对齐（≈1e-6）；收盘价因子非恒定。
- baostock 不提供面板基准 `000985`（`sh.000985` 返回 0 行）；
  `sh.000300`/`sh.000001` 可查到 2026-10-16。
- 本地 `_bench_000985.csv` 止于 2026-07-17。

## 适用边界
- 结论只针对"本地归档 ↔ baostock"这一对来源；换来源需重新量测。
- 价格基准对齐属于**数据工程**处理；一旦用于评分/回测，
  应在 manifest 中记录对齐方法与因子，保证可复现。
